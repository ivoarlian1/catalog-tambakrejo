# PROMPT PERBAIKAN LOGIN — E-CATALOG KELURAHAN TAMBAKREJO

Saya sedang mengembangkan aplikasi **E-Catalog Kelurahan Tambakrejo menggunakan Laravel** dan menggunakan **GitHub Copilot di VS Code**.

Aplikasi sudah berjalan dan memiliki sistem autentikasi untuk:

* Superadmin
* Catalog Admin

JANGAN membangun ulang sistem dari awal. Fokus pada **memperbaiki masalah login yang saat ini terjadi** tanpa merusak fitur, database, route, middleware, role, dan tampilan lain yang sudah berjalan.

## 1. PERBAIKI SHOW/HIDE PASSWORD PADA FORM LOGIN

Saat ini field password pada form login belum memiliki tombol untuk menampilkan/menyembunyikan password.

Perbaiki form login agar memiliki fitur:

* Field password tetap menggunakan `type="password"` secara default.
* Tambahkan tombol/icon mata di sisi kanan field password.
* Ketika icon ditekan:

  * password berubah menjadi teks yang terlihat (`type="text"`).
  * icon berubah menjadi indikator bahwa password sedang terlihat.
* Ketika ditekan kembali:

  * password kembali menjadi `type="password"`.
  * password kembali tersembunyi.
* Jangan mengubah nilai password ketika toggle dilakukan.
* Tombol tidak boleh menyebabkan form login langsung tersubmit.
* Gunakan `<button type="button">` untuk tombol toggle.
* Tambahkan `aria-label` yang sesuai agar tetap accessible.
* Pastikan fitur bekerja pada desktop dan mobile.

Jika project sudah menggunakan Bootstrap atau icon library yang sudah tersedia, gunakan library tersebut. Jangan menambahkan library baru jika tidak diperlukan.

Periksa seluruh komponen/view login yang digunakan dan pastikan tombol benar-benar muncul pada form login yang aktif.

---

# 2. PERBAIKI PESAN KESALAHAN LOGIN

Saat ini ketika pengguna melakukan kesalahan input login, jangan hanya menampilkan error teknis, exception, atau halaman error Laravel.

Tampilkan pesan yang mudah dipahami pengguna.

Gunakan pola berikut:

### A. Email/user ID tidak ditemukan atau kredensial salah

Tampilkan:

> Email atau password yang Anda masukkan salah.

Jangan memberitahu apakah email/user ID tersebut benar-benar terdaftar atau tidak.

Tujuannya agar sistem tidak membocorkan informasi keberadaan akun.

### B. Field kosong

Jika email/user ID kosong:

> Email atau user ID wajib diisi.

Jika password kosong:

> Password wajib diisi.

### C. Format email tidak valid

Jika login menggunakan email:

> Format email tidak valid.

### D. Akun tidak aktif

Jika sistem memiliki field/status `is_active`, dan akun ditemukan tetapi tidak aktif, tampilkan pesan yang sesuai, misalnya:

> Akun Anda tidak aktif. Silakan hubungi administrator.

Jangan mengubah struktur role atau sistem aktivasi yang sudah ada.

---

# 3. ERROR HARUS DITAMPILKAN DI FORM LOGIN

Pastikan validation error dan authentication error ditampilkan pada halaman login, bukan menyebabkan pengguna masuk ke halaman error.

Gunakan mekanisme Laravel yang sudah tersedia seperti:

* validation errors
* session flash message
* authentication error
* `@error`
* `$errors`
* atau mekanisme existing project yang sesuai.

Pesan harus tampil dengan jelas di dekat field atau pada alert di bagian form.

Contoh:

```text
⚠ Email atau password yang Anda masukkan salah.
```

Untuk validation:

```text
⚠ Email wajib diisi.
```

Jangan menampilkan:

```text
SQLSTATE[...]
```

atau:

```text
This site can't be reached
```

atau stack trace kepada pengguna.

---

# 4. PERBAIKI MASALAH "THIS SITE CAN'T BE REACHED" SETELAH LOGIN

Saat ini setelah melakukan login, aplikasi justru mengarah ke halaman:

> This site can't be reached

Ini harus diperiksa secara menyeluruh.

Jangan langsung mengubah route secara sembarangan.

Lakukan tracing alur login dari awal sampai akhir:

```text
Login Form
    ↓
POST Login
    ↓
Route
    ↓
Controller / Authentication Logic
    ↓
Validation
    ↓
Authentication
    ↓
Session
    ↓
Role Check / Middleware
    ↓
Redirect
    ↓
Dashboard
```

Periksa semua bagian tersebut.

---

# 5. PERIKSA ROUTE LOGIN

Periksa seluruh route yang berhubungan dengan autentikasi.

Cari route seperti:

```php
GET /login
POST /login
POST /logout
```

Pastikan:

* GET `/login` menampilkan form login.
* POST `/login` benar-benar menuju handler login yang benar.
* Route tidak mengarah ke URL yang sudah tidak ada.
* Tidak ada redirect ke hostname/domain yang salah.
* Tidak ada redirect ke port yang salah.
* Tidak ada redirect ke route lama.
* Tidak ada infinite redirect.
* Route name yang digunakan oleh `redirect()->route()` benar-benar ada.

Gunakan:

```bash
php artisan route:list
```

untuk memeriksa route aktual.

Jangan menghapus route yang masih digunakan fitur lain.

---

# 6. PERIKSA REDIRECT BERDASARKAN ROLE

Aplikasi memiliki minimal dua role:

* `superadmin`
* `catalog_admin`

Pastikan setelah login redirect berdasarkan role dilakukan dengan benar.

Contoh:

```text
superadmin
    → /superadmin

catalog_admin
    → /catalog-admin
```

Pastikan URL tersebut memang tersedia dan route-nya benar.

Jangan melakukan redirect ke URL hardcoded yang tidak diperlukan.

Lebih baik gunakan named route Laravel jika route name sudah tersedia:

```php
return redirect()->route('...');
```

daripada:

```php
return redirect('http://...');
```

atau URL hardcoded yang berpotensi menyebabkan masalah host/port.

---

# 7. PERIKSA MIDDLEWARE

Periksa middleware yang melindungi:

```text
/superadmin/*
/catalog-admin/*
```

Pastikan:

* user yang belum login diarahkan ke login.
* user yang sudah login tidak diarahkan kembali ke login secara tidak sengaja.
* `catalog_admin` tidak dapat mengakses halaman superadmin.
* `superadmin` tidak berubah menjadi `catalog_admin`.
* middleware tidak membuat redirect loop.

Pastikan session autentikasi Laravel tetap valid setelah login.

---

# 8. PERIKSA KONFIGURASI SESSION

Karena masalah terjadi setelah login, periksa konfigurasi session Laravel.

Periksa:

```text
.env
config/session.php
```

Perhatikan terutama:

```env
APP_URL=
SESSION_DRIVER=
SESSION_DOMAIN=
SESSION_SECURE_COOKIE=
```

Jangan mengubah konfigurasi secara membabi buta.

Sesuaikan dengan environment development yang sedang digunakan.

Jika aplikasi berjalan melalui:

```text
http://localhost
```

jangan sampai cookie/session dikonfigurasi sebagai HTTPS-only sehingga session tidak tersimpan.

Jika aplikasi berjalan melalui domain/virtual host tertentu, pastikan `APP_URL` dan konfigurasi session konsisten dengan alamat aplikasi yang sebenarnya.

---

# 9. PERIKSA APP_URL DAN REDIRECT URL

Cari kode yang melakukan redirect setelah login.

Cari kemungkinan kode seperti:

```php
redirect(...)
```

```php
to_route(...)
```

```php
route(...)
```

```php
url(...)
```

Periksa apakah ada URL seperti:

```text
http://127.0.0.1:xxxx
http://localhost:xxxx
https://...
```

yang tidak sesuai dengan alamat aplikasi saat ini.

Jangan mengganti URL hanya berdasarkan asumsi.

Identifikasi terlebih dahulu URL aktual yang menyebabkan:

> This site can't be reached

Kemudian perbaiki sumber redirect-nya.

---

# 10. JANGAN MENUTUPI ERROR SEBENARNYA

Jika ada exception Laravel yang menyebabkan login gagal, jangan sekadar menyembunyikannya.

Cari root cause-nya.

Periksa:

```text
storage/logs/laravel.log
```

dan browser/network request jika diperlukan.

Periksa juga response dari request:

```text
POST login
```

Cari apakah response menghasilkan:

* 302 redirect ke URL salah
* 404
* 419 Page Expired
* 403
* 500
* redirect loop
* connection refused
* hostname/port yang salah

Jika ditemukan error backend, perbaiki sumber masalahnya.

---

# 11. PERIKSA FORM ACTION DAN METHOD

Pastikan form login menggunakan:

```html
<form method="POST" ...>
```

dan memiliki:

```blade
@csrf
```

Pastikan `action` mengarah ke route login yang benar.

Jangan sampai form masih submit ke route lama.

Periksa juga:

* `name` field email/user ID
* `name` field password
* tombol submit
* CSRF token
* route name

Semua harus konsisten dengan controller/authentication logic.

---

# 12. JANGAN UBAH LOGIKA ROLE YANG SUDAH BENAR

Jangan membuat sistem login baru jika sistem yang ada sebenarnya sudah benar.

Pertahankan:

* role `superadmin`
* role `catalog_admin`
* hubungan Catalog Admin dengan catalog
* middleware authorization
* dashboard masing-masing role
* logout
* session Laravel

Fokus pada debugging dan perbaikan implementasi yang sekarang.

---

# 13. PERILAKU LOGIN YANG DIINGINKAN

Setelah perbaikan, alur harus menjadi seperti ini.

### Belum login

Pengguna membuka:

```text
/login
```

→ Form login muncul.

Jika username/email dan password benar:

```text
Login berhasil
↓
Session dibuat
↓
Role diperiksa
↓
Redirect ke dashboard sesuai role
```

### Credential salah

```text
Login
↓
Credential salah
↓
Tetap di halaman login
↓
Tampilkan:
"Email atau password yang Anda masukkan salah."
```

Password yang sebelumnya dimasukkan boleh dikosongkan kembali demi keamanan.

### Field kosong

```text
Submit
↓
Validation
↓
Tetap di halaman login
↓
Tampilkan pesan validation
```

### Logout

```text
Logout
↓
Session di-invalidate
↓
CSRF token diperbarui
↓
Kembali ke halaman login/public
```

Setelah logout, pengguna tidak boleh dapat membuka dashboard menggunakan tombol Back browser tanpa autentikasi ulang.

---

# 14. JANGAN MEMBUAT AUTO-LOGIN

Pastikan tidak ada mekanisme yang menyebabkan:

```text
Klik Login Catalog Admin
↓
langsung masuk dashboard
```

tanpa session autentikasi yang valid.

Perilaku yang benar:

```text
Belum login
→ tampilkan login form

Sudah login sebagai Catalog Admin
→ boleh diarahkan ke dashboard Catalog Admin

Sudah logout
→ harus login kembali
```

Jangan bypass middleware atau authentication hanya agar halaman dashboard bisa dibuka.

# 15. TESTING WAJIB

Setelah melakukan perubahan, lakukan testing minimal berikut.

### Test 1 — Login benar Superadmin

* Masukkan credential Superadmin yang valid.
* Klik login.
* Pastikan masuk ke `/superadmin`.

### Test 2 — Login benar Catalog Admin

* Masukkan credential Catalog Admin yang valid.
* Klik login.
* Pastikan masuk ke `/catalog-admin`.

### Test 3 — Password salah

* Masukkan user/email valid.
* Masukkan password salah.
* Pastikan tetap di halaman login.
* Pastikan muncul pesan:

  > Email atau password yang Anda masukkan salah.

### Test 4 — User/email salah

* Masukkan user/email yang tidak terdaftar.
* Pastikan tetap di halaman login.
* Pastikan muncul pesan generic credential salah.

### Test 5 — Field kosong

Pastikan validation message muncul dengan jelas.

### Test 6 — Show password

* Password default tersembunyi.
* Klik icon mata.
* Password terlihat.
* Klik lagi.
* Password tersembunyi kembali.

### Test 7 — Logout

* Login.
* Logout.
* Pastikan session berakhir.
* Buka dashboard secara langsung.
* Pastikan diarahkan kembali ke login.

### Test 8 — Refresh

Setelah login:

* refresh dashboard
* pastikan tetap login
* tidak muncul error
* tidak redirect ke hostname/port yang salah

### Test 9 — Browser Back

Setelah logout:

* tekan Back
* pastikan halaman protected tidak dapat digunakan tanpa autentikasi valid.

### Test 10 — Mobile

Periksa form login pada ukuran layar mobile.

Pastikan icon show/hide password tetap terlihat dan mudah ditekan.

# 17. HASIL AKHIR YANG HARUS DICAPAI

Setelah selesai, login harus memiliki kondisi:

```text
┌───────────────────────────────┐
│         LOGIN                 │
│                               │
│ Email / User ID               │
│ [________________________]    │
│                               │
│ Password              👁      │
│ [________________________]    │
│                               │
│ ⚠ Pesan error jika ada        │
│                               │
│        [ LOGIN ]              │
└───────────────────────────────┘
```

Dan alurnya:

```text
LOGIN
  │
  ├── Credential kosong
  │      └── Validation message
  │
  ├── Credential salah
  │      └── "Email atau password yang Anda masukkan salah."
  │
  ├── Credential benar
  │      │
  │      ├── Superadmin
  │      │      └── /superadmin
  │      │
  │      └── Catalog Admin
  │             └── /catalog-admin
  │
  └── Tidak boleh menghasilkan
         "This site can't be reached"
```

Sebelum menyatakan pekerjaan selesai, periksa kembali:

* route login
* controller authentication
* middleware
* session
* redirect
* APP_URL
* form action
* CSRF
* validation
* error handling
* browser/network response
* Laravel log

Jangan hanya memperbaiki tampilan form. **Pastikan root cause masalah “This site can't be reached” setelah login benar-benar ditemukan dan diperbaiki.**
