# ArcGIS External Workflow

Laravel and ArcGIS are separate systems:

- **Laravel** is the source of catalog data, coordinates, and stable detail URLs.
- **ArcGIS** is the external location-visualization system.

There is no runtime dependency, synchronization API, embedded map, or map UI in this MVP.

## Prepare Catalog Data

1. In Laravel, select a catalog with `Published` status. Draft catalogs are not public.
2. Read the catalog's `latitude` and `longitude` from its management form or public detail page. Coordinates may be empty until verified.
3. Copy the catalog name, category, address, coordinates, and detail URL. The detail URL follows `/katalog/{type}/{slug}`.
4. Confirm that the detail URL opens the intended published catalog before using it externally.

## Create an ArcGIS Marker

5. In the separate ArcGIS project, create or update a point using the latitude and longitude.
6. Add marker attributes for the catalog name, category, address, and Laravel detail URL.
7. Configure the marker's link to open the Laravel detail URL. If a QR is needed, use the catalog QR generated by Laravel; it encodes that URL, not coordinates or an ArcGIS URL.
8. Test the marker link and QR from a mobile device.

If a location changes, update the coordinates in Laravel and the point in ArcGIS. The catalog slug and QR destination remain unchanged.

## Data Handling

- Share only published catalog details intended for public access.
- Do not copy admin credentials or internal account information into ArcGIS.
- Coordinates are plain numeric values; Laravel does not render them on a map.
- This workflow is manual. No CSV export or synchronization API is provided by the MVP.
